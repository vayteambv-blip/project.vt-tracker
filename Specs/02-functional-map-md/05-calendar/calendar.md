# Календарь

Этот раздел описывает планирование проектов во времени.

## Что хранить

- проекты по направлениям работ;
- отдельный календарь для текущих проектов;
- отдельный календарь для будущих проектов, у которых уже есть дата старта;
- будущие проекты в календаре - это уже запланированные проекты, у которых дата старта назначена, но работа еще не началась;
- дату старта проекта, если она уже задана;
- дату окончания проекта, если она известна;
- фирму, которая будет исполнять работу;
- уведомление о старте за 10 рабочих дней.

## Что должно уметь

- показывать отдельный календарь для текущих проектов и отдельный календарь для будущих проектов по каждому направлению работ;
- открывать календарь по месяцам;
- видеть только текущие проекты;
- видеть только будущие проекты с назначенной датой старта;
- не показывать проект, если у него еще нет даты старта;
- если проект выбран из списка будущих проектов вне календаря и ему назначена дата, он сразу попадает в нужный календарь;
- если в календаре выбрать проект и дату старта, эта дата сразу сохраняется в проекте как дата старта;
- если дата старта задана в проекте, проект автоматически появляется в календаре;
- если дату старта изменить в календаре, она автоматически обновляется в проекте;
- если выбрано направление работ, проект показывается в календаре этого направления;
- видеть, какой проект стартует в конкретный день, если дата старта уже указана;
- видеть, когда проект должен закончиться, если дата окончания уже известна;
- видеть, какая фирма привязана к проекту;
- переносить старт проекта на другую дату прямо из календаря;
- видеть общий обзор по направлению и дате старта проекта.

## Что важно

- календарь показывает только текущие и будущие проекты;
- проекты без даты старта в календаре не показываются;
- отдельные записи работ в календаре не нужны;
- календарь нужен для обзора, а не для дублирования данных.
- слова `текущий` и `будущий` в календаре относятся к планированию, а не к отдельным статусам проекта.
