# Календарь

Этот раздел описывает планирование проектов во времени в одном календаре.

## Что хранить

- проекты по направлениям работ;
- один календарь со списком проектов, которые уже готовы к показу по дате старта;
- дату старта проекта, если она уже задана;
- диапазон рабочих дней;
- уведомление о старте за 10 и 5 рабочих дней на сайте.

## Что должно уметь

- показывать один календарь по направлениям работ;
- открывать календарь по месяцам;
- видеть только проекты, у которых уже назначена дата старта;
- не показывать проект, если у него еще нет даты старта;
- если проект выбран из списка черновиков вне календаря и ему назначена дата, он сразу попадает в нужный календарь;
- если в календаре выбрать проект и дату старта, эта дата сразу сохраняется в проекте как дата старта;
- если дата старта задана в проекте, проект автоматически появляется в календаре;
- если дату старта изменить в календаре, она автоматически обновляется в проекте;
- если выбрано направление работ, проект показывается в календаре этого направления;
- видеть, какой проект стартует в конкретный день, если дата старта уже указана;
- переносить старт проекта на другую дату прямо из календаря;
- видеть общий обзор по направлению и дате старта проекта;
- показывать текущие и будущие проекты отдельными списками;
- сохранять синхронизацию между календарем и проектом в обе стороны.

## Что важно

- календарь показывает только проекты с назначенной датой старта;
- проекты без даты старта в календаре не показываются;
- текущий проект - это проект, который уже стартовал;
- будущий проект - это проект, у которого уже есть дата старта, но старт еще не наступил;
- отдельные записи работ в календаре не нужны;
- календарь нужен для обзора, а не для дублирования данных;
- напоминание приходит только на сайте;
- если проекта нет в календаре, значит у него еще не назначена дата старта;
- календарь не создает новые сущности.
