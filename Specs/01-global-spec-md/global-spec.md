# Бизнес-контекст

Этот файл фиксирует общую логику проекта до перехода к Functional Spec.

## 1. Суть проекта

- Проект создается для строительной компании в Бельгии.
- Основной пользователь - я, как главный администратор.
- На первом этапе это только фронтенд-сайт.
- Сайт должен удобно работать и на телефоне, и на компьютере.
- Проект нужен для контроля, управления и организации строительных проектов.
- Проект должен экономить время на управлении и планировании.

## 2. Что решает проект

- видеть текущие и будущие проекты;
- понимать статус каждого проекта без лишнего поиска;
- планировать сроки и этапы;
- отслеживать расходы;
- хранить документы, фото и файлы;
- вести периодические отчеты;
- хранить архив завершенных проектов;
- быстро находить нужный проект по году, месяцу, разделу и клиенту;
- видеть итог по проекту и прибыль;
- работать без лишнего дублирования и мусора;
- использовать шаблоны уже сейчас.

## 3. Термины проекта

- Проект - это основная строительная единица.
- Клиент - это заказчик проекта.
- Один проект связан с одним клиентом.
- У одного клиента может быть много проектов.
- Если появляется другая работа, для нее создается отдельный проект.
- У проекта есть четыре статуса:
  - подготовка;
  - первый этап;
  - второй этап;
  - сдача.
- Статус проекта меняется вручную.
- Слова `будущий` и `текущий` относятся к календарю и планированию, а не к отдельным статусам проекта.

## 4. Клиенты

Клиенты - это только частные клиенты.

Для каждого клиента хранятся общие данные:

- имя;
- фамилия;
- телефон;
- email;
- связанные проекты.

Для клиента отдельно хранится адрес проживания.

## 5. Фирмы и рабочие

- Фирмы могут участвовать в разных проектах.
- В проекте я прикрепляю нужную фирму-субподрядчика.
- У фирмы нет фиксированного направления работ как постоянной специализации.
- Направление работ задается на уровне проекта.
- У фирмы должна быть отдельная страница со всеми ее данными.
- У фирмы нужно хранить все файлы, документы и информацию отдельно.
- У фирмы нужно хранить рабочих, которые к ней привязаны.
- Рабочие всегда привязаны к определенной фирме.
- У фирмы нужно хранить текущих рабочих и историю всех рабочих, которые работали через эту фирму.
- У фирмы нужно хранить документы рабочих, которые работали через эту фирму.
- У фирмы нужно хранить отдельный обзорный список проектов, в которых она участвовала.
- История рабочих в проектах не нужна.
- Фирма может быть и фирмой-исполнителем, и фирмой-заказчиком в разных проектах.

## 6. Проекты

- Для каждого проекта хранить:
  - дату старта, если она уже задана;
  - дату окончания, если она уже известна;
  - текущий статус;
  - адрес проекта.
- У проекта только одно направление работ.
- У проекта может быть список фирм, участвующих в этом проекте.
- Проект можно создать заранее без даты старта.
- У фирмы нет отдельного финансового блока; ее оплата всегда идет через расходы проекта.
- До запуска проект хранится как подготовка и остается вне календаря, пока не задана дата старта.
- Перед созданием проекта должны быть указаны:
  - название проекта;
  - данные самого проекта;
  - данные клиента;
  - адрес;
  - email;
  - номер телефона;
  - смета, заранее одобренная клиентом.
- При создании проекта обязательна только согласованная смета, остальные документы можно добавлять позже.
- Текущий контракт для создания проекта не обязателен.
- Смета может меняться со временем.
- Можно добавлять дополнительные работы и отдельные суммы к смете.
- Это касается и сметы клиента, и предложения фирмы-субподрядчика.
- Дополнительные работы внутри текущего проекта идут отдельной строкой; если речь о другой сфере работ, создается отдельный проект.
- При добавлении нового файла старый остается прикрепленным, но должно быть понятно, где старый и где новый.
- Когда я решу начать проект, я перевожу его в нужный этап и задаю дату старта.
- Дата окончания может быть пустой, пока проект еще не завершен.
- Завершенный проект я переношу в архив вручную кнопкой.
- Если нужно, завершенный проект можно вернуть из архива обратно кнопкой.
- У проекта хранятся связанные документы, стартовые фото объекта, фото процесса, фото в отчетах, отчеты и связь с календарем через дату старта.
- Эти три группы фото не смешиваются между собой.
- У проекта хранится список материалов с количеством, единицами и отметкой закуплено.
- Все эти данные привязаны к карточке проекта и открываются внутри него, а календарь обновляется через дату старта.
- У проекта должен быть отдельный список отчетов, и в каждом отчете можно хранить фотографии отдельно от фото процесса.
- После создания проект можно редактировать.

## 7. Виды работ

Проекты делятся на четыре основных направления:

- кровля и строительство крыш;
- фасады;
- внутриотделочные работы;
- глобальная стройка, строительство домов и каркасов.

Каждый проект относится только к одному направлению.

Проект показывается через:

- календарь;
- список проектов;
- отчеты по этапам;
- прикрепленные фирмы и рабочих.

## 8. Расходы и финансы

Расходы ведутся только в финансах и привязываются к каждому проекту.

Типы расходов:

- подготовка и сдача объекта;
- материалы;
- оплата фирмам;
- аренда техники;
- непредвиденные расходы.

Проект должен уметь:

- показывать итог по каждому проекту;
- показывать итог по оплатам фирмам внутри проекта;
- делать финальный подсчет в конце проекта.

Аналитика по прибыли = базовая смета плюс дополнительные работы минус все расходы.

## 9. Календарь

- Нужны отдельные календари по каждому направлению работ:
  - кровля;
  - фасады;
  - внутриотделочные работы;
  - глобальная стройка.
- В календаре должны быть отдельные разделы:
  - для текущих проектов;
  - для будущих проектов с назначенной датой старта.
- Будущие проекты в календаре - это уже запланированные проекты с датой старта, но еще не начатые.
- Проекты без даты старта остаются в списке будущих вне календаря, пока дата старта не назначена.
- В каждом календаре должно быть видно:
  - дату старта проекта, если она задана;
  - возможную дату окончания проекта;
  - фирму, которая будет исполнять работу.
- Проекты без даты старта в календаре не показываются.
- Если проект выбран из списка будущих проектов вне календаря и ему назначена дата, он сразу попадает в нужный календарь.
- Если в календаре выбрать проект и дату старта, эта дата сразу сохраняется в проекте как дата старта.
- Если дата старта задана в проекте, она автоматически появляется в календаре.
- Если дату старта изменить в календаре, она автоматически обновляется в проекте.
- Если выбрано направление работ, проект попадает в календарь этого направления.
- Для проекта, у которого уже задана дата старта, нужны уведомления за 10 рабочих дней до старта.
- Календарь должен открываться по месяцам.
- В календаре я должен видеть, какой проект стартует в конкретный день.
- Я должен иметь возможность перенести старт проекта на другую дату.
- Через календарь я должен видеть обзор по каждому направлению и дате старта проекта.

## 10. Периодические отчеты

- Периодические отчеты делаю только я.
- Отчет нужен для фиксации выполненных работ и прогресса проекта.
- В каждом отчете:
  - текст;
  - фотографии без ограничения по количеству.

## 11. Документы и файлы

Документы проекта и фирмы хранятся отдельно друг от друга.

По каждому проекту нужно хранить документы внутри общего типа хранения `Документы`, где лежат:

- смета;
- текущий контракт;
- акты сдачи, если они есть;
- другие нужные файлы и документы по проекту без ограничений по типу.

Другие нужные файлы - это любые файлы и документы без ограничений по типу.

## 12. Шаблоны

Проект должен поддерживать:

- шаблоны проектов;
- шаблоны фирм.

Шаблон - это заготовка с нужными полями и данными, которую можно использовать как основу для проекта или фирмы.

Автозаполнение не нужно.

## 13. Архив

- Нужно хранить архив завершенных проектов.
- Архив должен быть отдельным блоком.
- Архив должен быть удобно отсортирован по годам.
- В архиве я должен быстро выбирать нужный год, месяц, раздел и клиента.
- Архив должен открываться и быть доступным для поиска.
- По умолчанию архив открывается на текущем году.
- Разделы в архиве - это 4 направления работ:
  - кровля и строительство крыш;
  - фасады;
  - внутриотделочные работы;
  - глобальная стройка, строительство домов и каркасов.

## 14. Четыре уровня хранения

- Глобально в системе: клиенты, проекты, фирмы, рабочие, документы, фото, календарь, расходы, отчеты, архив, шаблоны.
- Внутри проекта: клиент, одно направление работ, связанные фирмы, документы, стартовые фото, фото процесса, фото в отчетах, отчеты, материалы, статус, даты, адрес, итог и связь с календарем через дату старта.
- Внутри фирмы: данные фирмы, документы, рабочие, отдельные файлы и информация.
- Внутри клиента: данные клиента, связанные проекты и адрес проживания.

## 15. Доступ

- Сейчас полный доступ есть только у меня.
- В будущем можно будет добавить любое количество админов с полным доступом.
- Дополнительные админы должны иметь такой же доступ, как и у меня.

## 16. Важное ограничение

- На первом этапе проект остается только фронтендом.
- Ничего лишнего и дублирующегося добавлять не нужно.
- Все описания должны быть понятными и по делу.
