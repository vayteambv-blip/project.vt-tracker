# Проекты

Этот раздел описывает главный объект системы.
Один проект соответствует одной работе и одному направлению.

## Что хранить

- название проекта;
- дата старта, если она уже задана;
- дата окончания, если она уже известна;
- диапазон рабочих дней;
- статус проекта из четырех этапов:
  - подготовка;
  - первый этап;
  - второй этап;
  - сдача;
- адрес проекта;
- клиент;
- одно направление работ;
- несколько субподрядчиков, участвующих в проекте;
- документы;
- отдельный список отчетов проекта;
- материалы;
- итог по проекту.

## Что должно уметь

- создавать проект;
- создавать проект заранее как подготовленный;
- перед созданием проверять наличие:
  - названия проекта;
  - данных самого проекта;
  - данных клиента;
  - адреса;
  - email;
  - номера телефона;
  - сметы, заранее одобренной клиентом;
- связывать проект с клиентом;
- задавать одно направление работ для проекта;
- переводить проект в нужный этап вручную;
- задавать дату старта;
- прикреплять субподрядчика к проекту;
- добавлять документы;
- добавлять отчеты с фотографиями;
- вести список материалов по проекту с количеством, единицами и галочкой закуплено;
- закрывать проект вручную;
- после создания проект можно редактировать;
- проверять полноту данных проекта перед сохранением;
- показывать, чего не хватает, прямо в форме создания;
- если проект заполнен не до конца, его можно сохранить как черновик и вернуться к нему позже.

## Что важно

- проект и объект считаются одним и тем же;
- у проекта один клиент;
- у клиента может быть много проектов на разных локациях;
- достаточно только адреса проекта;
- проект относится только к одному направлению;
- в проекте может быть несколько субподрядчиков;
- карточка проекта должна показывать, какие субподрядчики участвуют в проекте;
- в карточке проекта не хранить лишние дубли по субподрядчикам;
- документы, отчеты и материалы относятся к проекту и живут в своих отдельных блоках;
- фотографии хранятся только внутри отчетов;
- отдельного архива старых фото нет;
- фото в процессе хранятся внутри отчетов;
- отдельные записи работ не хранятся как сущности;
- рабочих отдельно в проекте не хранить;
- общие заметки по проекту не хранить, заметки идут внутри отчетов;
- проект должен быть основой для всех остальных данных;
- если проект заполнен не до конца, это должно быть заметно сразу;
- в списке проектов должно быть видно название и статус;
- проект считается заполненным, когда есть название, данные проекта, данные клиента, адрес, email, телефон и согласованная смета;
- дата старта может быть пустой, если проект еще не запущен;
- незаполненный проект можно сохранить как черновик, чтобы вернуться к нему позже без потери данных.
