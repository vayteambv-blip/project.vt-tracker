# Future Spec

Этот спек описывает только будущие уточнения после `Global Spec` и `Functional Map`. Здесь не повторяются уже закрытые правила текущей функциональной карты.

## 1. Цель спека

- держать только то, что еще может быть расширено или уточнено позже;
- не смешивать будущие решения с текущими функциями;
- сохранять проект в логике поэтапного развития.

## 2. Что уже закрыто

- общий смысл проекта;
- клиенты;
- субподрядчики;
- проекты;
- календарь;
- архив;
- документы;
- финансы;
- отчетность;
- основные правила хранения и связей между сущностями.

## 3. Что может уточняться дальше

- более подробные сценарии роста системы после текущей функциональной базы;
- возможные новые удобства для администрирования, если они появятся позже;
- дополнительные улучшения интерфейса, если они не меняют текущую модель данных;
- будущие расширения, которые пока не должны попадать в текущие спеки.

## 4. Что не должно попадать в Future Spec

- технические решения;
- дублирование `Global Spec`;
- дублирование `Functional Map`;
- уже закрытые правила текущего функционального слоя;
- случайные идеи без связи с проектом;
- лишние сущности и мусорные заготовки;
- детали, которые относятся к технике, а не к будущему развитию проекта.

## 5. Как заполнять

- писать коротко;
- держать все по порядку;
- не повторять уже зафиксированное;
- уточнять только то, что действительно нужно для следующего этапа;
- если что-то уже согласовано, не переносить это повторно.

## 6. Финальная проверка

- перед переходом дальше проверить, нет ли дублей;
- убедиться, что блоки не спорят между собой;
- оставить только то, что реально помогает развивать проект дальше;
- не переносить в следующий спек уже закрытые правила.
