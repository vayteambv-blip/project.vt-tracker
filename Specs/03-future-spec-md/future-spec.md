# Future Spec

Этот спек описывает только будущие уточнения после `Global Spec` и `Functional Map`. Здесь не повторяются уже закрытые правила текущей функциональной карты.

## Активный режим второго плана

- этот файл включается после завершения первого плана из `Work Plans`;
- здесь остаются только будущие уточнения и расширения;
- ничего из уже закрытой функциональной базы сюда не переносится повторно;
- перед любым изменением сначала проверяется, не относится ли оно уже к текущему слою.

## 1. Цель спека

- держать только то, что еще может быть расширено или уточнено позже;
- не смешивать будущие решения с текущими функциями;
- сохранять проект в логике поэтапного развития.

## 2. Что уже закрыто

- общий смысл проекта;
- клиенты;
- субподрядчики;
- проекты;
- календарь;
- архив;
- документы;
- финансы;
- отчетность;
- основные правила хранения и связей между сущностями.

## 3. Что может уточняться дальше

### 3.1 Документы

- загрузка и скачивание файлов как отдельное действие, если это потребуется позже;
- отдельный архив версий документа;
- отправка документа по email прямо из карточки;
- возврат старой версии как основной;
- шаблоны документов как отдельная будущая заготовка для проекта и субподрядчика.

### 3.2 Субподрядчики

- более подробная карточка субподрядчика;
- история прикрепленных документов и контрактов;
- архив рабочих внутри субподрядчика;
- отдельный финансовый обзор по месяцам и годам, если такая часть появится позже.

### 3.3 Администрирование

- добавление и подтверждение новых админов;
- будущие роли и права доступа;
- любые отдельные административные экраны, если они не входят в текущую базу.

### 3.4 Интерфейс

- будущие улучшения интерфейса, если они не меняют текущую модель данных;
- любые расширения, которые пока не должны попадать в текущие спеки.

## 4. Что не должно попадать в Future Spec

- технические решения;
- дублирование `Global Spec`;
- дублирование `Functional Map`;
- уже закрытые правила текущего функционального слоя;
- случайные идеи без связи с проектом;
- лишние сущности и мусорные заготовки;
- детали, которые относятся к технике, а не к будущему развитию проекта.

## 5. Как заполнять

- писать коротко;
- держать все по порядку;
- не повторять уже зафиксированное;
- уточнять только то, что действительно нужно для следующего этапа;
- если что-то уже согласовано, не переносить это повторно.

## 6. Финальная проверка

- перед переходом дальше проверить, нет ли дублей;
- убедиться, что блоки не спорят между собой;
- оставить только то, что реально помогает развивать проект дальше;
- не переносить в следующий спек уже закрытые правила.
