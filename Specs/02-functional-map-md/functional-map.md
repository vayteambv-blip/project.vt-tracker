# Functional Map

Этот спек разбивает проект на восемь отдельных функциональных блоков. Каждый блок описывает свою часть системы и не должен смешиваться с другими без необходимости.

## 1. Clients

Клиенты - это заказчики проектов: частные заказчики и фирмы-заказчики.

В этом блоке описано:
- создание клиента;
- хранение данных клиента;
- привязка клиента к проектам;
- просмотр карточки клиента;
- проверка полноты данных клиента.

У клиента хранятся общие данные и связь с проектами. Документы клиента не используются.

Подробности:
- [`01-clients/clients.md`](./01-clients/clients.md)

## 2. Firms

Фирмы - это отдельные субподрядчики или фирмы-заказчики, которые участвуют в проектах.

В этом блоке описано:
- создание фирмы;
- хранение данных фирмы;
- текущие рабочие;
- история рабочих;
- документы фирмы;
- контракты фирмы;
- список проектов фирмы;
- привязка фирмы к проекту;
- проверка полноты данных фирмы.

Фирма не является клиентом и не хранит постоянную специализацию по работам.

Подробности:
- [`02-firms/firms.md`](./02-firms/firms.md)

## 3. Projects

Проект - это отдельная строительная работа.
Один проект соответствует одной работе и одному направлению.

В этом блоке описано:
- создание проекта;
- обязательная смета;
- связь с одним клиентом;
- одно направление работ;
- даты проекта;
- документы;
- фото;
- отчеты;
- архивирование;
- синхронизация с календарем;
- финансовая связка с проектом;
- общий статус проекта;
- список материалов по проекту;
- список фирм, которые участвуют в проекте.

Проект может быть подготовленным, иметь дату старта, идти по этапам и завершаться вручную.

Подробности:
- [`03-projects/projects.md`](./03-projects/projects.md)

## 4. Finances

Финансы отвечают за все денежные расчеты проекта.

В этом блоке описано:
- расходы по типам;
- итог по проекту;
- итог по фирме;
- остаток до оплаты;
- прибыль;
- расчет суммы на основе сметы, допработ и расходов.

Расходы ведутся только здесь и не дублируются в проекте.

Подробности:
- [`04-finances/finances.md`](./04-finances/finances.md)

## 5. Calendar

Календарь нужен для планирования проектов во времени.

В этом блоке описано:
- календари по направлениям работ;
- текущие проекты;
- будущие проекты;
- дата старта;
- диапазон рабочих дней;
- дата окончания;
- привязка фирмы к проекту;
- перенос даты старта;
- синхронизация между календарем и проектом;
- уведомления перед стартом.

Календарь показывает только проекты и не хранит отдельные задачи или работы.
Каждый проект должен быть виден в календаре каждый день в пределах своего диапазона рабочих дней.

Подробности:
- [`05-calendar/calendar.md`](./05-calendar/calendar.md)

## 6. Reports

Отчеты нужны для короткой или подробной фиксации выполненных работ.

В этом блоке описано:
- создание отчета;
- заголовок отчета;
- текст отчета;
- фотографии в отчете;
- сортировка по дате создания;
- редактирование отчета;
- удаление отчета;
- привязка отчета к проекту.

Отчеты ведутся только внутри проекта.

Подробности:
- [`06-reports/reports.md`](./06-reports/reports.md)

## 7. Docs / Templates

Документы и шаблоны отвечают за хранение файлов и заготовок.

В этом блоке описано:
- документы проекта;
- документы фирмы;
- текущая и архивные версии файла;
- типы файлов;
- фильтры;
- отправка на email;
- скачивание;
- восстановление старой версии;
- шаблоны проектов;
- шаблоны фирм.

Документы клиента в систему не входят.
Старые версии файлов должны сохраняться и быть доступными для открытия и скачивания.
Если документ заменяется, старая версия остается в истории.
У файла должно быть не больше 2 старых версий, и они должны быстро открываться.
Старую версию нужно открывать прямо из карточки файла без долгого поиска.
В карточке файла должно быть сразу понятно, где текущая версия, а где старые версии.
Если документ относится и к проекту, и к фирме, старые версии должны быть видны в обоих местах.

Подробности:
- [`07-docs-templates/docs-templates.md`](./07-docs-templates/docs-templates.md)

## 8. Archive

Архив хранит завершенные проекты и помогает быстро находить старые данные.

В этом блоке описано:
- перенос проекта в архив;
- возврат проекта из архива;
- поиск по году;
- поиск по месяцу;
- поиск по разделу;
- поиск по клиенту;
- структура архивных разделов по направлениям работ;
- открытие архива по умолчанию на текущем году.
- в архиве видеть проект целиком на момент закрытия.

В архив попадают только завершенные проекты.
Если проект возвращается из архива, он продолжается как тот же самый проект, а не как новый.

Подробности:
- [`08-archive/archive.md`](./08-archive/archive.md)

## Правило

- Каждый блок отвечает только за свою часть.
- Одинаковые данные не дублируются без необходимости.
- Функции описываются по порядку, чтобы потом их было легко переносить в следующие спеки.
- У списков должно быть понятное пустое состояние.
- Если данных много, для просмотра должны быть фильтры или поиск.
- Если данных не хватает, это должно быть видно прямо там, где идет заполнение.
- Если данных не хватает, это должно подсвечиваться заметно и не давать продолжить, пока не исправлено.
- Если не хватает нескольких вещей, ниже должен быть короткий список того, чего именно не хватает.
- Рядом с ошибкой должна быть короткая подсказка, что именно нужно добавить или исправить.
- Поиск и фильтры должны помогать быстро находить нужные проекты, фирмы, документы и архив.
- В приоритете должны быть быстрый просмотр и скачивание, а история версий должна быть доступна отдельно.
- Для нового клиента, фирмы или проекта должны быть заполнены минимальные обязательные поля, иначе сохранение блокируется.
- Уже введенные данные не должны пропадать при обновлении страницы, если форма еще не завершена.
- Если страница обновилась, уже введенные данные должны остаться на месте.
- После поиска должен быть быстрый переход в нужную карточку.
- При открытии проекта сразу видно, какие фирмы в нем участвуют.
- Итог по проекту должен быть виден только в финансах, без отдельного дублирования в карточке проекта.
- В списке проектов должно быть видно название и статус для быстрого понимания.
- Если проект заполнен не до конца, это должно быть заметно сразу.
- Внутри проекта должен быть быстрый обзор фирм, документов, отчетов и материалов.
- При создании клиента или фирмы система тоже должна блокировать сохранение, пока не заполнены обязательные поля.
- При создании проекта система должна сразу показывать, чего не хватает, и не давать сохранить, пока это не исправлено.
- Для проекта с назначенной датой старта должно приходить напоминание за 10 рабочих дней и еще раз за 5 рабочих дней.
- Напоминание должно приходить отдельным сообщением по email и WhatsApp.
- Если данных не хватает, должно быть короткое предупреждение о том, что именно нужно дописать, прямо в месте заполнения.
- Фильтры помогают смотреть данные, но не создают новые сущности.
